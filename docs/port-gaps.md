# The endpoint audit

Every operation the Clojure service serves is now served here. This file records how the
gaps were found, what they were, and -- because it is the part that matters going forward --
what the guard test does and does not prove.

## What was missing

A route-level audit on 2026-08-21 found **eleven** operations the Clojure service serves and
this one did not. They had gone unnoticed through two phase sign-offs because nothing had
ever compared the two route inventories.

The audit started from the shadow harness's error-code coverage report, which showed
`ERR_INVALID_PAGE`, `ERR_PAGE_NOT_POS` and `ERR_CHUNK_TOO_SMALL` to be unreachable. They are
raised only by `page_tabular.clj`, and the endpoints that reach it had not been written.

| Operation | Reached through |
|---|---|
| `GET /data/{data-id}/manifest` | terrain `GET /secured/filesystem/file/manifest` |
| `GET /data/{data-id}/chunks` | terrain `POST /secured/filesystem/read-chunk` |
| `GET /data/{data-id}/chunks-tabular` | terrain `POST /secured/filesystem/read-tabular-chunk` |
| `POST /creatability-marker` | terrain `can-create-folder` |
| `POST /stat-lister` | terrain's paged stat by uuid |
| `GET /navigation/root` | terrain `list-roots` |
| `GET /navigation/home` | no caller found |
| `GET /data/{data-id}/permissions` | no caller found |
| `GET /data/by-path/manifest/{path}` | no caller found |
| `GET /data/by-path/chunks/{path}` | no caller found |
| `GET /data/by-path/chunks-tabular/{path}` | no caller found |

The first three back file preview in the DE, and terrain relays this service's status and
body verbatim on all of them, so a cutover would have surfaced as a 404 on every preview.

A twelfth gap was found on 2026-08-24, and it is the interesting one: **`GET
/data/path/{zone}/*` serves a folder listing for a collection and the file's own bytes for a
data object**, and only the folder half had been written. The route was registered, so a
comparison of route inventories reported it as served while a download answered
`ERR_NOT_A_FOLDER`. Nothing at the route level could have caught it.

All twelve were ported on 2026-08-24.

## Why the swagger capture is a complete inventory

`TestEveryClojureRouteIsServedOrAccountedFor` compares what this service registers against
`testdata/contract/swagger-clojure.json`, the Clojure service's own `/swagger.json` captured
at phase 0. That document is generated by compojure-api, which **omits any route marked
`:no-doc`** -- so it is worth saying why nothing hides in that gap.

Five data-info routes are `:no-doc`, and each is the wildcard twin of a documented route:

| Undocumented route | Documented twin |
|---|---|
| `GET /data/path/:zone/*` | `GET /data/path/{zone}/{path}` |
| `GET /navigation/path/:zone/*` | `GET /navigation/path/{zone}/{path}` |
| `GET /data/by-path/manifest/*` | `GET /data/by-path/manifest/{path}` |
| `GET /data/by-path/chunks/*` | `GET /data/by-path/chunks/{path}` |
| `GET /data/by-path/chunks-tabular/*` | `GET /data/by-path/chunks-tabular/{path}` |

The pairs exist because compojure cannot document a wildcard: the `*` route is the one that
serves, and the `:path` twin exists to be documented. Two of the twins are literally dead
code returning `{:status 501}`; the other three are shadowed by the wildcard route declared
above them. Normalising a wildcard to `{path}` maps each pair onto one operation, which is
what `servedOperations` does.

Enumerating the routes directly from the Clojure source -- every `context`, `GET`, `POST`,
`PUT`, `DELETE`, `HEAD` and `PATCH` form under `src/data_info/routes/` -- yields **59**
operations, and the captured document contains the same 59. So the document is the whole
surface, not most of it.

## What the guard proves, and what it does not

It proves that no operation the Clojure service serves is unregistered here, on every build.
`notYetPorted` is the escape hatch: an entry there says a gap has been counted and named
rather than discovered at cutover, and the test fails if an entry is added without the
Clojure service serving it, or left in place after the route is registered.

It does **not** prove that a registered route behaves like its counterpart -- the download
gap is exactly that failure -- and it does not look at request or response shapes. Those are
the shadow harness's job. Two checks were run alongside the route comparison and are worth
repeating if this is ever audited again:

- every service function the Clojure routes dispatch to (55 of them, plus `GET /` and
  `/admin/config`) has a Go counterpart;
- every query and body key data-info's schemas declare appears somewhere in the Go tree.

Neither is a substitute for the harness. They are cheap, and they are what turned up the
download gap.
